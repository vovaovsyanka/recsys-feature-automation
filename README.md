# Автоматизация построения признаков в рекомендательных системах

Исследование по заданию «можно ли заменить ручное конструирование признаков в рекомендательной системе автоматическим подходом
без потери качества». Основной датасет — Yambda-50M (Яндекс.Музыка), для проверки обобщения — KION (МТС).
Устройство кода — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md);
проверка источников — в [`docs/SOURCES.md`](docs/SOURCES.md); протокол, зафиксированный до основных запусков, — в [`docs/DESIGN.md`](docs/DESIGN.md).

## Что внутри

```
src/recsys/          библиотека: данные, протокол, кандидаты, признаки, модели, поиск признаков, метрики
scripts/             по одному скрипту на эксперимент; номер скрипта = номер эксперимента (E01 … E33)
experiments/         результаты экспериментов: config.json, results.json, log.txt, env.json, README.md
docs/                источники, дизайн исследования, описание архитектуры, индекс экспериментов
```

## Установка

Python 3.11, Windows или Linux. Для эксперимента с графовой моделью и моделью над историей нужен GPU с CUDA (проверено на RTX 3050, 4 ГБ).

```bash
python -m venv .venv
.venv\Scripts\activate                       # Linux: source .venv/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt
pip install -e .
```

Оперативной памяти нужно около 32 ГБ (пик — 20 ГБ у отдельных экспериментов), места на диске — около 60 ГБ (кэш признаков).

## Запуск

Данные скачиваются и готовятся одной командой (около 0,5 ГБ):

```bash
python scripts/00_prepare_data.py
```

Эксперименты запускаются по очереди — по одному, иначе тайминги будут искажены, а компьютер перегружен:

```bash
python scripts/run_pipeline.py --list              # этапы с оценкой времени и состоянием
python scripts/run_pipeline.py --group core        # основные эксперименты
python scripts/run_pipeline.py --group extended     # дополнительные: OpenFE, ИИ-агент, эмбеддинги, масштабирование
```

Уже выполненные этапы пропускаются (`--force` — пересчитать, `--only 08,17-A2_B` — выбрать этапы). Отдельный эксперимент
запускается напрямую, например `python scripts/08_baseline_gbdt.py`. После прогона `python scripts/99_make_index.py` собирает
таблицу длительностей в `docs/EXPERIMENT_INDEX.md`.

Полезные переменные окружения:

| переменная | назначение |
|---|---|
| `RECSYS_THREADS` | число потоков LightGBM (по умолчанию 8 из 12; уменьшите, если компьютер зависает) |
| `OLLAMA_API_KEY`, `OLLAMA_API_KEY2` | ключи Ollama Cloud для эксперимента с ИИ-агентом (E14); при исчерпании лимита берётся второй ключ |
| `RECSYS_LOCAL_URL`, `RECSYS_LOCAL_MODEL` | запасной локальный сервер с OpenAI-совместимым API (LM Studio, по умолчанию `http://localhost:1234/v1`) |

## Эксперименты

| № | эксперимент | вопрос |
|---|---|---|
| E01–E02 | аудит данных Yambda и KION | совпадают ли данные с документацией |
| E03–E04 | кандидаты и метки | какой набор кандидатов и каков потолок качества |
| E05 | проверка на утечки | не использует ли признак события после момента прогноза |
| E06 | эвристики | что даёт одна лишь популярность или личный счётчик |
| E07–E08 | ручные признаки и базовый бустинг | сильный базлайн |
| E09 | аблация и окна | какие группы признаков важны и насколько зависит от выбора окон человеком |
| E10–E14 | автоматический поиск признаков | случайный выбор, отбор из пула, OpenFE, обучаемые окна, ИИ-агент |
| E15 | модель над историей | заменяет ли внимание к сырой истории ручные агрегаты |
| E16 | ALS и LightGCN | дают ли графовые представления сигнал, которого нет в агрегатах |
| E17–E18 | финальные модели и оценка | сравнение всех подходов с доверительными интервалами; единственное обращение к test |
| E19–E20 | масштабирование и стоимость | как результаты зависят от объёма данных и сколько стоят признаки |
| E30–E33 | KION | те же вопросы на втором датасете |

## Воспроизводимость и честность оценки

* Разбиение глобальное по времени; метки обучения заканчиваются до начала val, метки val — до test (проверяется в коде).
* Признаки читают только события до момента прогноза; это проверяется автоматически (E05): будущее заменяется мусором, признаки не должны измениться.
* Выбор признаков и гиперпараметров идёт только по train и val. Каждое обращение к test пишется в `experiments/test_access_log.jsonl`.
* Тайминги экспериментов осмысленны только при запуске на свободной машине.
